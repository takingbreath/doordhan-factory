# The QC gate (2026-09-28)

`pipeline/qc_gate.py` is now the last step of producing (playbooks/produce.md step 11). No final reaches Akhilesh without its stamp.

## What it runs, in order
1. **Script diff.** It compares the final's Scribe transcript, bound to that exact audio, with the frozen approved script. It also re-checks the frozen file's sha256.
2. **Lip-sync.** `lipsync_lag` runs on every talking segment of the final, against the reel's audio.
3. **Face consistency.** Each talking clip, over the span the edit uses, is compared with the character sheet.
4. **Mix.** `verify_line` runs its end, tail and lead checks on each line as placed in the mix. It uses the build's dialogue stem, which has the same placement, trims and fades.
5. **Loudness.** Within ±1 LU of the target, with true peak at or below −1 dBTP.
6. **Length and format.**

## Repairs and blocking
Three faults are repaired automatically, once: the gate writes the repairs file, rebuilds and re-checks.
- **Constant lip-sync offset:** the clip's src_in moves, or the part's `audio_shift_ms` in edit.json.
- **Hard-cut line end:** the line re-ends at its last word with a fade. If the file itself stops hot but Scribe heard the word, it gets an 80 ms fade.
- **Wrong lead:** the cut to the talking shot moves, and src_in moves with it.

Anything else blocks, and the summary names the check, the clip and the fix.

## How it is enforced
The gate is enforced, not advisory:
- A SendUserFile PreToolUse hook (`.claude/settings.json` → `pipeline/hooks/require_qc_stamp.py`) refuses to send an unstamped video from outputs/.
- `put_upload.py` does the same for the Higgsfield upload behind the email link.
- The stamp covers the exact sha256, so any change after the gate voids it.
- The hook was tested live: it refused E5 v1.

## Results on E5
**The approved v4 is BLOCKED** (`qc_gate_E5_v4.txt`). Two real findings:
- **Lip-sync P4:** the known −160 ms tail of the 11 s neighbour line. The windows run −80 to −160 ms, and a −80 ms src_in shift centres them.
- **Mix P6:** the "का" ends at speech level, only 4 dB down in the last 40 ms. The raw ElevenLabs file ends the same way.

**The rebuilt candidate v5 PASSES** with both faults repaired automatically (`qc_gate_E5_v5.txt` and `.png`):
- **P4:** src_in moved by −0.080 s, and the median offset went from −120 to −40 ms.
- **P6:** an 80 ms fade takes the end to 12 dB down.
- **Transcript:** the fade changed the sound, so v5 needed its own transcript. It matches the script 7/7.
- **Everything else is unchanged from v4.**

The build edits reproduce v4 exactly, picture and sound, when no repairs are applied.

## False alarms fixed while calibrating on v4
- **Face on the final:** captions flying over the face, the crash zoom and a face cut off by the frame edge scored 0.33–0.47 on frames that are plainly Pandey. The check now scores the talking clip over the used span, where every line scores 0.61–0.72 worst-frame.
- **Mix window:** P1's file has trailing silence that overlaps P2's first word in the stem. The window now stops at the next line.
- **lipsync_lag offset repair:** it only offered a shift when the median was outside the pass window. It now offers one whenever all judged windows fit inside at once, centring them on −40 ms.
